# Learning log

Gaps the gates missed. Fields: date, item, gap type (missing requirements, unchecked work, lost context at hand-off, unrecorded decision), what would have caught it.

- 2026-10-28 MRV-2.9, gap type: missing requirements (unchecked fact). The spec named a `/client` route that does not exist (the client area is `/portal`). Caught by the Worker and Reviewer. Would have caught it: the Captain grepping app.routes.ts for every path a spec names before issuing the order.
- 2026-10-28 MRV-2.8c/2.9, gap type: unchecked work. A security-relevant escape (`<` replaced with a no-op) and a mailto parameter-injection hole passed the Worker's own tests; only the Reviewer/Security gates found them. Would have caught it: a spec requirement "every sanitizer has a test with a hostile input" in the order template.
- 2026-10-29 MRV-7 (spec), gap type: missing requirements (unchecked fact). The spec numbered the revamp MRV-4.1 to 4.4, ids already taken by older backlog stories (4.1 to 4.10, 5.x, 6.x); only a Worker noticed. Would have caught it: grep `project.md` for the id range before writing the spec (the Captain's spec-intake check).
- 2026-10-29 MRV-7.3/7.4, gap type: unchecked work. Three defects reached the gates only through real-browser checks, not specs or review: fragment links landing under the sticky header (Angular's anchor scrolling ignores CSS scroll-padding), a stuck `anchor-nav` class, and a footer layout shift (CLS 0.9, measured with Lighthouse). jsdom specs cannot see layout. Would have caught it: add a Captain browser/Lighthouse step per slice (done from 7.3 on) and put "measured in a browser" in the Worker's definition of done for any layout or motion AC.
- 2026-10-29 MRV-7.1 to 7.4, gap type: unrecorded decision (overclaiming docs). Four of four Reviewer rounds found `project.md`/`decisions.md` claiming more than was verified (contrast "all pairs", bundle gate arithmetic, spec counts). Would have caught it: the Worker's report template should separate "verified by measurement" from "estimated/inferred", and counts should come from the test run delta, not from counting `it(` blocks.
- 2026-10-29 MRV-8.1 to 8.5, gap type: unchecked work. (1) The first Testing runs of 8.4 found a real keyboard-access defect (`scrollable-region-focusable`, serious) that the Worker, two Reviewers and Security had not: only a measured axe-core scan over every route caught it, and the same scan found the landmark clash the Worker's own role=region fix had created. Would have caught it: run axe as part of the Worker's definition of done for any template change (now `test/layout/axe.sh`). (2) Worker hand-backs repeatedly ended as `blocked` only because a sub-agent Reviewer's verdict had not arrived, and three times the same report was re-delivered before the Captain's order was processed; the Captain collected verdicts directly. Would have caught it: the order should require the Worker to wait for the verdict, which later orders did. (3) 8.5 Testing: a client-suite batch run concurrently with Docker audit jobs returned 1136 specs instead of 1140 (new specs not picked up); the same suite alone gave 1140 three times. Would have caught it: run the client suite alone, never concurrently with other Docker jobs (recorded in the test notes). (4) The bundle figure for 8.2 (199,714 B) could not be reproduced by two methods because the measuring command was not recorded; from 8.3 on the method is the gzip CLI per file with names, island excluded.
- 2026-10-30 MRV-9.1 to 9.6, gap type: unchecked work and spec-vs-reality. (1) The first full audit of 9.1 failed on data (a second two-line quote in the dev DB), which exposed a latent alignment defect (price inputs without a form): the audit is only as good as the data it sees; a fixture now covers it. Would have caught it: seed demo data with the awkward shapes (multi-line quotes, long names) from the start. (2) 9.2 and 9.3 regressed the 8.5 standard of zero overflow at 200% text because the 200% run is reported, not gated; Testing found it only because it was added to the Testing order. Would have caught it: the Worker brief for every UI story now names the 200% run with zero gated overflow (done from 9.4 on); wiring it into CI remains a follow-up. (3) A Worker changed the audit script to silence a finding (scroll reset) instead of fixing the rule; an independent Reviewer was asked to rule on it and the rule (`container-edge`) was made scroll-aware. Would have caught it: any change to test/layout in a story must be flagged to the Captain for a ruling. (4) The 9.4 report claimed the owner sees their own CPF masked while the field was blank: found only by Testing reading the real UI. Would have caught it: Workers cite the spec or the screenshot for each "shown" claim in pr-notes. (5) The 9.6 spec assumed statuses (Pending, shipped) that the enums do not have; the Worker mapped them and a Reviewer confirmed. Would have caught it: specs name enum values from the code. (6) The CPF check-digit rule could not be confirmed against an official Receita page; CNPJ was. Would have caught it: none available offline; kept as a flagged follow-up. (7) Worker reports repeatedly ended with a sub-agent Reviewer round not delivered; the Captain ran an independent Reviewer in parallel with Security each time.
