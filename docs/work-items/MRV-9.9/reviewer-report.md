## Risky behaviour
- Per-process cache: multi-replica lag up to 60 s, and SQL/migration-written statuses lag up to 60 s (documented). Password reset, when built, must respect it (documented).
- The cache race handling (generation re-check) and the 10,000-entry bound are untested (decisions.md admits). The `Clear()` at the bound makes a burst of 10,000 distinct suspended-token lookups hit the DB again; no security impact (fail toward the database), only load.
- Gate does one DB read per Client-token request per customer per minute at most; a database error in the gate yields a 500 for that request, including public endpoints with a customer token (previously public endpoints never needed the DB for auth). Low.
- A cached `null` (missing account) is treated as not suspended: a deleted account's token passes the gate (unchanged behaviour, other checks handle it).
- Interceptor ends the session for a suspended answer on any request; a concurrent burst of requests calls `endSuspendedSession` + `navigateByUrl('/login')` repeatedly (idempotent).
