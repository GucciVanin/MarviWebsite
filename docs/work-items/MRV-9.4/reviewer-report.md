## Targeted checks
- Field-type exclusivity: business fields on a personal account give 400 (`RegistrationRules.cs:261-265`, field `registration`); CPF or birth date on a business account give 400 (:213-216). Empty strings count as absent. Met.
- Age: `IsAdult = birth <= today.AddYears(-18)` (:311). 29 Feb births count from 1 March, consistent server and client. Clock: `BrazilDate` is fixed UTC-3 (no DST in Brazil since 2019); client `todayInBrazil` matches. No test exercises `BrazilDate` itself around UTC midnight (minor); API tests pin the day via `IBrazilDate`.
- Masks: CPF is only returned as `CpfMasked`; `Snapshot` and the reveal audit use masks; no logger call in the Identity folder touches registration data.
- Production: guard requires `Privacy:CpfHashKey` (32+ chars, no example marker) and `DataProtection:KeysPath`, refuses `Ephemeral`; compose mounts the keys volume; Dockerfile creates `/keys`. The dev `appsettings.json` hash key contains `CHANGE-ME`/`dev-only`, which the guard rejects in Production.
- Migration: Up default Business, Down drops indexes and columns; documented SQL lists accounts still lacking data. Consequence: existing Approved customers cannot fill in their own CNPJ (owner lock), so an admin must type each one (operations.md step 2 says so).
