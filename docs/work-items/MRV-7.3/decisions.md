# Decisions

## Page transitions and anchors (AC-13, AC-14)
- **`withViewTransitions({ skipInitialTransition: true, onViewTransitionCreated })`** next to the existing `withInMemoryScrolling({ anchorScrolling: 'enabled', scrollPositionRestoration: 'enabled' })` (already configured, unchanged). The hook is `core/motion/view-transition.ts` (`skipViewTransitionOnReducedMotion`, takes the `reduced()` predicate so it is testable): under `prefers-reduced-motion: reduce` it calls `transition.skipTransition()`. Without the View Transitions API the router never creates a transition, so navigation is the old one. The `PageTitleStrategy`/`SeoService` run on navigation as before; no code of theirs was touched.
- **Global CSS** in the new `styles/_motion.scss`: `::view-transition-old(root)` fades out and `::view-transition-new(root)` fades in with a 0.6 rem rise, both `var(--motion-base)` (300 ms) with the token easings. Under reduce every `::view-transition-*` animation is `none !important` (second line of defence; the router already skips).
- **Header and footer stay still:** `view-transition-name: site-header` on the `app-header` host (already `position: sticky`) and `site-footer` on the `app-footer` host (given `display: block`, which it already was as a flex item of the shell). Their groups get `animation-duration: 0s`, the old snapshot is `display: none` and the new one has no animation, so they never fade or slide.
- **Smooth anchors without slowing page changes.** `scroll-behavior: smooth` on `html` would also make the router's scroll-to-top on a normal page change glide under the view transition. So `core/motion/anchor-scroll.ts` sets `html.anchor-nav` on `NavigationStart` only when the target URL has a fragment, and the CSS makes scrolling smooth only for `html.anchor-nav`, inside `@media (prefers-reduced-motion: no-preference)`. **Round 2 (browser finding B):** the class used to stay on until the next navigation (it was still set 2.5 s later). It is now removed one animation frame after the router's `Scroll` event (the scroll call has run by then; a smooth scroll already started keeps going), and at once on `NavigationCancel` and `NavigationError`; a later plain `NavigationStart` also clears it (back/forward, initial load). Specs cover end (Scroll then frame), cancel, error, no-fragment and plain-after-fragment.
- **Landing below the sticky header (round 2, browser finding A):** the first version only set CSS `scroll-padding-top: 5.5rem`, which the browser showed is not honoured: Angular's `anchorScrolling` goes through `ViewportScroller` and `window.scrollTo(top - offset)`, not `scrollIntoView`, and the real header is 136 px tall on desktop (two rows). Now `core/motion/header-offset.ts` (`observeHeaderOffset`) measures the sticky header with a `ResizeObserver` (started in `AppHeader` after first render, disconnected on destroy) and publishes height + 8 px as `--scroll-offset` on `<html>` (CSS `scroll-padding-top`, which still serves focus and native fragment scrolling) and through `ViewportScroller.setOffset(() => [0, offset])`, a function so it is read live at each scroll. The token's `5.5rem` stays only as the value before the first measurement. The `scroll-margin-top` rules (home sections, reviews, `<main>`) stay removed so offsets do not add up. Without `ResizeObserver` the offset is set once. Specs: published value, resize, disconnect, no-RO fallback.
- **Anchor targets are never transformed (round 2):** `getBoundingClientRect` includes a pending reveal's 1.25 rem translate, so `#rede` (a stat tile) landed about 20 px off. The `#rede` `li` no longer carries `appReveal`; its icon and text block do. No other anchor target (`#sobre`, `#por-que`, `#produtos`, `#avaliacoes`) has a reveal on the element itself.

## Feedback (AC-15)
- Nav links: the 2 px `border-bottom` became an `::after` indicator that scales in from the left (`transform: scaleX`), on hover, keyboard focus and the active page. Footer: links nudge 3 px right on hover and press back; social icons lift 2 px and scale on press. Cards: `.card--interactive` presses (`scale(0.99)`) and also lifts on `:focus-visible`; the storefront `.product-grid > .product` lifts on hover; category tiles gain a shadow, a press state and an arrow nudge; review arrows and the WhatsApp button lift/press. All durations and easings are tokens (the WhatsApp button used `0.15s ease`, now tokens). `.btn` already had hover/press/focus from 7.1.
- **Mobile menu** (below 1024 px): the nav is now an absolutely positioned panel under the bar (`inset: 100% 0 auto 0` of the sticky host) that fades and slides with `opacity` and `transform`. Closed it is `visibility: hidden` with the visibility transition delayed by `--motion-base`, so its links leave the tab order and the accessibility tree as `display: none` did, and the fade-out still plays. The state class is still `header__nav--open` and `aria-expanded` is unchanged. Visible difference: the menu now overlays the page instead of pushing it down.
- **Privacy notice** enter and exit both work, with Angular's own `animate.enter` / `animate.leave` (Angular 22, not `@angular/animations`): CSS keyframes slide it up and fade it in, and on "Entendi" it slides down and Angular removes the element when the animation ends. Under reduced motion the keyframes are `none`, so Angular removes it at once. The existing specs (removed right after click and `detectChanges`) pass unchanged in jsdom.

## Reveal on scroll (AC-16)
- `appReveal` (`shared/ui/reveal/reveal.ts`, selector `[appReveal]`, optional stagger index, capped at 8). In `afterNextRender`, and only if `IntersectionObserver` exists and reduced motion is off, it adds `reveal` (translated 1.25 rem and transparent) and observes; on the first intersection it adds `reveal--in`, disconnects and drops the observer; `DestroyRef` disconnects too. Anywhere else (no API, reduced motion, tests, print) it adds nothing, so content is visible. Pending state is `.reveal:not(.reveal--in)`; the reveal itself is a keyframe animation with `animation-fill-mode: backwards` and a delay of `--reveal-index * --reveal-step` (80 ms), so it holds no transform afterwards and hover lifts on the same card keep working.
- **Already on screen at attach (round 2, finding C):** in `arm`, an element whose rectangle is already inside the observed area (same 92 % line as the root margin) is left exactly as it is: no `reveal` class, no observer, so there is no hide-then-fade flash for above-the-fold items (contact card, first flow items). A side effect is that catalog cards that arrive already on screen after the data loads also appear without the fade. Elements below the fold go false then true through the observer as before.
- **Reveal and count-up race (finding C):** both now use the same `REVEAL_ROOT_MARGIN` (`core/motion/viewport.ts`). The number sits inside its tile, so the tile intersects first or together with it; the count (800 ms) starts when the number crosses the same line and runs alongside the tile's 800 ms fade, so a stat and its number appear together rather than the number finishing in an invisible tile. A spec asserts the directive uses that margin; the count-up uses the same constant in code and is not separately asserted.
- Used on: home flow heading and four steps, four stat tiles, six category tiles (wrapper `li`, not the link), products intro, closing banner; storefront product cards (`$index % 4`); contact form card and details. Not on the hero (LCP/first view), the review carousel items (clipped by their scroll container, they would stay hidden until scrolled) or the privacy policy text (a long plain document, nothing sensible to stagger). Only transform/opacity, so no layout shift; nothing in the SEO/JSON-LD logic reads these elements (it writes to `<head>`).

## Skeletons (AC-17)
- `LoadState` has `variant: 'text' | 'cards'` (default `'text'`, default markup untouched, so the portals are unchanged) and `skeletonCount` (default 6). `cards` renders `div[role=status].product-grid.load-state--cards` (round 2, finding D: the `load-state` flex class is no longer on it, so it keeps `.product-grid`'s own gap and stretch; it has the same `1em` block margin as the `ul` it is replaced by) with a visually hidden "Carregando…" and `.skeleton-card` placeholders (`aria-hidden`), used by the storefront product grid. The deals list keeps the text variant.
- Reviews: `GoogleReviewsSection` shows a `reviews-skeleton` section (hidden status text, same two-column layout, three cards) only while the request is in flight; on success the real section replaces it, on failure/empty it disappears like before. That last case does move the content below it, but it is far below the fold on first load, so it does not count as visible layout shift; the Captain should confirm in the browser.
- Shimmer: a light band in `::after` moves with `transform: translateX` in `@media (prefers-reduced-motion: no-preference)`; static grey otherwise.

## Reduced motion and transform/opacity (AC-18, AC-19)
- Tokens already go to 0 ms. Additionally: view-transition animations `none !important`, `.reveal` visible and `.reveal--in` animation `none` (also for print), shimmer only under `no-preference`, `.icon-spin` `animation: none` under reduce, notice keyframes `none`, directive adds nothing, router skips the transition, smooth scrolling only under `no-preference`.
- **How AC-19 was checked (no browser):** I grepped every `transition`, `animation` and `@keyframes` in `client/src`. Animated properties are only `transform`, `opacity` and, for hover colour feedback, `color`, `background(-color)`, `border-color`, `box-shadow`, `text-decoration-color`; the mobile menu additionally transitions `visibility` (discrete, no layout). No `width`, `height`, `top`, `left`, `margin` or `padding` is animated; the nav indicator uses `scaleX`, the menu `translateY`. The skeleton and real cards share dimensions (`min-height` on the skeleton). A real CLS measurement was **not** done.

## Not verified
The Captain's browser pass found A to D (round 2 fixes them); the fixes themselves are covered by specs but were **not** re-checked in a browser: that fragment links land below the 136 px header at desktop and phone widths (the ViewportScroller offset), that `html.anchor-nav` really clears after the scroll, no flash on above-the-fold reveals, the count-up/tile timing, and that the skeleton grid matches the product grid with no shift. Still never viewed: the page cross-fade and header/footer staying still, the sticky header's `view-transition-name` stacking, the mobile panel slide and alignment, notice enter/exit (`animate.leave` in a real browser), skeleton appearance, reduced-motion end to end, and CLS = 0 on the home page. The portals inherit the global rules but were not looked at.
