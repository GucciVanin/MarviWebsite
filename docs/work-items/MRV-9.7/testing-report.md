## Browser walk-through (built-in browser, throwaway `marvi-audit`, seeded)
- **Novo produto with a photo:** the file chooser is a labelled file input in the "Foto do produto (opcional)" group with the hint "JPEG, PNG ou WebP, até 5 MB, com pelo menos 400 x 400 pixels. É a foto que a loja mostra." A real canvas-encoded JPEG 800x600 uploads at once (`POST /api/admin/media/product-photos` 200); the preview shows the file served from the same origin (`/api/public/media/products/<32 hex>.jpg`, decoded 800x600), the status reads "Foto enviada: cerveja-800x600.jpg (17 KB). Ela passa a valer quando você salvar o produto.", the label changes to "Trocar foto" and a "Remover foto" button appears.
- **Remove:** "Remover foto" returns to "Escolher foto" and the neutral hint with no preview. **Replace:** PNG 600x600 (360 KB) then WebP 900x700 (11 KB): preview source changes each time and decodes at the new size.
- **Save:** SKU, name, category, description, "Volume: 600 ml", two prices and two quantities filled; `POST /api/admin/products/with-setup` 201, notice "Produto criado: Cerveja Foto 9.7 (FOTO-97-A)".
- **Admin table thumbnail:** the new row shows the WebP thumbnail (900 px source) with `alt` = product name; 6 seeded rows also have thumbnails.
- **Storefront card:** photo, name, description ("Descricao de teste ..."), attribute "Volume 600 ml", category, SKU, the deal price and "Disponível". 7 photo images on the page, all decoded.
- **Picker, basket, quote line:** as the demo customer, the picker shows the thumbnail for the new product (9 rows, photo decoded 900x700, `alt=""` beside the name as designed); "Adicionar" puts it in the basket with the photo; "Solicitar cotação" ("Cotação enviada!") and the quote line in "Minhas cotações" carries the photo. Order lines were not driven in the browser (covered by API tests and the runtime suite).
- **Refusals (pt-BR):** SVG file: "Use uma foto JPEG, PNG ou WebP." (field `aria-invalid`, no upload request); GIF: same message; 200x200 PNG: "A foto deve ter pelo menos 400 x 400 pixels."; 6.7 MB PNG: "A foto deve ter no máximo 5 MB."; an SVG renamed `falso.png` with an image type is not trusted by name: the API answers 400 and the panel shows "Use uma foto JPEG, PNG ou WebP.". Nothing was linked to a product in any of these cases.
- **CSP:** the page CSP is unchanged (`default-src 'self'; ... img-src 'self' data: ...`). Photos load under it (every `/api/public/media/products/*` request 200, images decode); the browser console has no CSP or "Refused to" message. The only console errors are the expected 400 (spoofed SVG upload) plus an earlier 409 and 400s from the pages visited. Through nginx the photo response has the API's `public, max-age=31536000, immutable`, `nosniff` and `default-src 'none'; sandbox`.
- **Keyboard only:** tab order in the edit panel is description > file chooser > "Remover foto" > Ativo; each stop shows a 2 px solid outline (`:focus-visible` true). With real Tab/Enter key events: Enter on "Remover foto" removes the photo, focus moves to the chooser, and the status (`role="status"`) announces "A foto será removida quando você salvar o produto." Saving then returned 204 style notice "Produto salvo", the table thumbnail disappeared and the file now answers 404 from the API (the browser still showed 200 from its one-year cache). Not exercised: the operating-system file dialog that Enter/Space on the chooser opens (cannot be driven from this pane); chooser selection in the walk-through was made by setting files on the input with the same change event.
