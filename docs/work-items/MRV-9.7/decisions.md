# decisions

- Captain (spec, 2026-11-03, reversible): photos are uploaded files on a persistent volume, served same-origin so the CSP is untouched; upload first, link by token in the product save; JPEG/PNG/WebP, 5 MB, 400..6000 px, by bytes; metadata not stripped; one photo per product; the free-text image address is removed and old values set to NULL.
- **One product path kept (MRV-9.8).** There is no "attach photo" endpoint. `photoToken` (create and edit) and `removePhoto` (edit) ride on `POST .../with-setup` and `PUT .../{id}`; the token row is removed and `Product.ImageUrl` set in the SAME `AuditLogger.TrySaveAsync` save. The image rule left `ProductRules` (`ProductInput.ImageUrl`/`ProductPlan.ImageUrl`, `CheckImageUrl`, the contract file's image limit and cases are gone); the file is judged by `ProductPhotoRules`, which `SingleProductPathTests` now allows next to `ProductRules` (it judges a file, not a product field). The IsActive-only exception does not apply when a token or `removePhoto` is present. A token together with `removePhoto` is a 400 on `photo`.
- **Token = the stem of the stored name** (128 random bits, hex). A row in `product_photo_uploads` exists only while the photo waits; spending it deletes the row in the product save, so "already used" is simply "no row". Owner = the admin's user id (another admin's token is refused with the same generic message as an unknown, expired or malformed one; nothing about the token is revealed). Expiry: an hour, checked on use and by the cleanup.
- **Cleanup** removes upload rows older than an hour plus a 10 minute grace (a save that resolved a token just before it expired must not lose its file to a tick already running; rows are removed first and only then their files), files older than that which no product and no upload refers to, and half-written temp files. It runs at start and every 15 minutes (`Media:CleanupMinutes`) as a hosted service that the test host does not register; tests call `ProductPhotoService.CleanupAsync` and move time with an `AdjustableClock` (`TimeProvider` registered in DI).
- **Failures of the product save** leave the token and the file untouched (the audit factory test); two requests spending one token: the loser's save raises a concurrency exception, which the controller turns into a 400 on `photo` (checked on real Postgres in the runtime suite; EF's InMemory provider has no concurrency check, so there is no API unit test for it).
- **Request size.** `[RequestSizeLimit(6 MB)]`, `[RequestFormLimits(MultipartBodyLengthLimit = 6 MB)]`, an explicit `Content-Length` check (413 before anything is read) and nginx `client_max_body_size 6m` for that one location. `[ApiController]` reads the form before the action and turns a too-large body into a generic 400, so the action carries `[ReadsItsOwnForm]` (removes the form value providers) and reads the form itself, answering 413. Over a real socket a client still writing a huge body may see the connection closed rather than the 413; both mean "cut off" (the runtime test accepts either).
- **Rate limit** policy `productPhoto` (30/min per address, `RateLimiting:ProductPhoto`, 100000 in the dev compose and the test host), plus at most 50 waiting uploads per admin (429), so repeated chooser use cannot fill the disk between cleanups.
- **Polyglots.** The parser requires a perfect structure (JPEG ends exactly at EOI; PNG chunks with valid CRCs end exactly at IEND; WebP chunks tile the RIFF size) so nothing can trail, and metadata/text parts (JPEG non-scan segments, PNG chunks other than IDAT, WebP chunks other than the image) are searched for `<script`, `<html`, `<svg`, `<?php`, `<!doctype`, `<iframe`, `javascript:`. An earlier version searched the whole file; the Reviewer pointed out that compressed pixel data would spell a marker by chance in about 1% of large photos, so only metadata is searched now. Served files also carry `nosniff` and a `default-src 'none'; sandbox` CSP. Lossless/arithmetic JPEG (SOF3+) and animated WebP are refused as not web photos.
- **Serving.** `GET /api/public/media/products/{name}` accepts only `^[0-9a-f]{32}\.(jpg|png|webp)$`; the storage re-checks every name and the resolved path. nginx gets a `^~` location that proxies it without `Cache-Control: no-store`.
- **Migration.** Clears `image_url` except paths of ours (`/api/public/media/products/%`), so Down then Up does not orphan uploaded photos; Down drops the table only (cleared addresses are not restored, said in the migration, `docs/operations.md` section 9 and pr-notes). `test/runtime/migration-photos.sh` (port 55437).
- **Production guard.** `Media:Path` missing in Production is a problem (the exemption `Deployment:AllowExampleSecrets` is used by compose, which also sets `Media__Path=/media`). Outside Production the folder defaults to `media` beside the binaries.
- **Client.** The chooser uploads at once (a `blob:` preview would break the CSP) and previews from the answered same-origin address; the pixel size is read with `createImageBitmap` (no drawing) and left to the API when the browser cannot say. Saving waits for a photo in flight (Reviewer finding) and an upload that ends after the form was reset is dropped; any upload failure shows a message (the generic one when the body names no field). The shared `app-product-photo` only draws `/api/public/media/products/` paths, so a stray old external address can never be requested. Its placeholder is an inline SVG (not `app-icon`, so icon assertions elsewhere do not change). Drag and drop was not built (optional in the spec).
- **Storefront card (AC-6).** Photo, name, SKU chip, category chip (`CategoryName` added to the list DTO), price, stock, the description clamped to three lines (hidden from screen readers when long, its full text is behind "Ver detalhes"), the first four attributes as a labelled list and the rest behind "Ver detalhes". There is no separate product detail page, so the card is the detail.
- **Thumbnail alt text.** Spec says the product name as alt text everywhere; the line and table thumbnails therefore repeat the adjacent name for a screen reader (Reviewer note, kept per spec; axe is clean).
- **Seed.** `deploy/seed-demo.mjs` generates a flat PNG per product in code and uploads it through the real endpoint (six products with a photo, two without, one with seven attributes and a long description) so the dev stack and the audits show cards with and without photos.
- **Deviations from the spec text:** none in behaviour. Not built: drag and drop (optional), a delete-pending-upload endpoint (the cleanup covers it).
- **Accepted limit of the polyglot check (Reviewer round 2).** Markup hidden inside compressed pixel data (JPEG scan data, a stored deflate block in IDAT, VP8/VP8L/ALPH data) is not detectable without decoding and is accepted; what neutralises it is how photos are served: the content type of the validated extension, `nosniff` and `default-src 'none'; sandbox`. Metadata and text parts are still searched and refused.
- **Order of the conflict answers (Reviewer round 2).** When a save fails on a race, "SKU taken" (409) is answered first and "token already used" (400 on `photo`) only when the SKU is free, so a retry after a lost response still gets the `sku` answer the form expects.
- **Deviation from AC-5 wording, forced by the axe gate:** thumbnails that sit beside the product's name as text (picker, basket, quote and order lines of both portals) carry an empty `alt`, because axe-core reports `image-redundant-alt` (minor) for the name repeated and the gate is 0 violations. Cards and the admin table (name in another cell) keep the product name as alt. The name is still read from the adjacent text.
