# PR notes MRV-9.7 (issue #59)

Closes #59. Spec: `docs/specs/MRV-9.7-product-photo.md`.

**Behaviour changes to review**
- **The free-text image address is gone** from the product panel and from the `with-setup` / `PUT` request bodies (a body that still sends `imageUrl` is accepted and the field ignored). `ProductRules` lost its image rule and the contract file its image limit and cases. A product photo is an uploaded file: `POST /api/admin/media/product-photos` answers `{photoToken, previewUrl}`; `with-setup` and `PUT` take `photoToken` (and `PUT` `removePhoto`) and link it in the SAME audited save as the product (one product path, MRV-9.8; no attach endpoint).
- **Migration `ProductPhotos` sets every existing `products.image_url` that is not one of our paths to NULL** (old https addresses could never display under the CSP). `Down` drops the new table and cannot restore the cleared addresses: back up the database before migrating. `bash test/runtime/migration-photos.sh` 12/12 on a throwaway Postgres. The dev database was migrated when the dev stack restarted (its demo products have no photos until the owner runs `reset-dev.sh`).
- **Ops needs:** a persistent media volume. Compose declares `marvi-media` at `/media` (`Media__Path`); **in Production the API refuses to start without `Media:Path`**. Back the volume up with the database; size roughly products x photo size (5 MB at most each). `docs/operations.md` section 9.
- **nginx:** a 6 MB request body only for `= /api/admin/media/product-photos` (everywhere else the 1 MB default stays; checked through nginx: 3 MB 200, 5.5 MB 400 from the API, 6.5 MB 413 from nginx, 1.5 MB on the import 413), and a location for the public photos without `no-store` so the API one-year immutable cache applies. The CSP is unchanged (`img-src 'self' data:`); photos load under it (checked in a browser: eager cards decoded at 480x480, an 800x600 WebP preview in the panel, no CSP console message).
- **Public route** `GET /api/public/media/products/{name}`: stored-shape names only (32 hex + jpg/png/webp), else 404; `nosniff`, `default-src 'none'; sandbox`, `public, max-age=31536000, immutable`.
- **Upload limits:** Admin only; rate-limit policy `productPhoto` (30/min); request cap 6 MB (413), file cap 5 MB, 400..6000 px, JPEG/PNG/WebP by bytes and a full parse (trailing data, bad CRCs, lossless JPEG, animated WebP, SVG, GIF, HEIC, PDF refused); at most 50 waiting uploads per admin; a cleanup (at start and every 15 min) removes uploads older than an hour (plus 10 min grace) and files nothing refers to.
- **Privacy: photos keep their metadata** (EXIF, GPS if recorded). Not stripped in this story (no image dependency); follow-up. The files are public by design. Said in `docs/operations.md` section 9, `architecture.md` and `CONTEXT.md`.
- **Storefront card** now shows photo (or a neutral placeholder), name, SKU, category, description (3 lines; full text behind "Ver detalhes" when long) and the attributes (first four, rest behind "Ver detalhes"). The list API carries `Description` and `CategoryName`; quote and order line DTOs carry `ImageUrl`.
- **Deviation from AC-5 wording:** thumbnails beside the product name as text (picker, basket, quote and order lines) have `alt=""` because axe flags the repeated name (`image-redundant-alt`, gate 0). Cards and the admin table keep the name as alt.
- **Not built:** drag and drop (optional), several photos, resizing, CDN, metadata stripping, CSV photos.
- Seed: `deploy/seed-demo.mjs` uploads a generated PNG for six of the eight demo products.
